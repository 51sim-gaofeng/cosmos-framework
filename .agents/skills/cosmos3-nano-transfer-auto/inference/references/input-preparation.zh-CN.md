<a id="check-transfer-auto-inputs"></a>
# 检查 Transfer-Auto 输入

检查相机身份、控制数据、描述文本和时间关系，确保它们彼此对应，并符合所选模型的要求。

<a id="options-and-scope"></a>
## 选项与范围

- “向我展示选项和默认值。”解释工作流，不要求提供媒体，也不启动工作。
- “检查我的请求、控制、标定和渲染器设置，不要生成。”进行检查并提出建议，不重写或启动任务。
- “在新文件夹中为这些场景准备描述文本和请求。”仅编写并打包所请求的输出，保留原始输入。

默认只进行检查。阅读实际清单字段和已安装运行时的读取器；
资产清单不等同于可执行的推理请求。将准备好的请求交回
[cosmos3-nano-transfer-auto-inference](../README.zh-CN.md) 执行生成。
不要擅自切换运行时／检查点，或调用外部付费描述文本服务。

<a id="1-establish-the-actual-run"></a>
## 1. 确认实际运行配置

阅读请求、所选权重／模型版本和运行时版本，以及提供的解析后参数／日志。
记录视角、控制、所选区间和场景属性。区分物理源通道与模型相机别名。

根据实际字段而非请求文件名，判断是否使用初始 RGB 条件。
检查每台相机实际读取的文本；导出结果中出现了场景级提示词，不代表各视角实际使用了这段文本。
不要将 I2V 与仅 WSM 的生成作比较，却把差异归因于描述文本。

<a id="2-map-physical-cameras-to-learned-identities"></a>
## 2. 将物理相机映射到模型已学习的视角身份

<a id="choose-reference-rig-or-custom-rig-generation"></a>
### 选择参考相机组或自定义相机组生成

已发布的 Auto 模型针对参考相机组进行了优化。可以尝试自己的相机组，
但随着相机位置、朝向、FOV、镜头投影和重叠范围与训练几何的差异增大，应预期质量下降。

根据生成输出所需的相机视点作出选择：

- **从参考相机组的视点生成。** 遵循随附的
  [场景转换技能](../../../cookbooks/cosmos3/simulation/auto/wsm/skills/scenario-to-rds-hq/SKILL.md)
  及其 [Hyperion 重定向指南](../../../cookbooks/cosmos3/simulation/auto/wsm/skills/scenario-to-rds-hq/references/hyperion-retargeting.md)。
  提供的 `retarget_hyperion.py` 辅助工具使用经过验证的 RDS-HQ 场景标注和车辆位姿，
  为随附的十一相机 Hyperion 相机组写入相机位姿与内参。然后使用该标定渲染 WSM，
  使用相应相机键，并为渲染出的视角准备描述文本。
  这样可使渲染视角匹配已发布模型的相机几何。
- **从自己的相机组视点生成。** 保留实际标定，为这些相机渲染 WSM。
  使用下方的 [Camera Rig Explorer 工作流](#use-camera-rig-explorer-for-your-own-rig)，
  综合方向、FOV、投影、位置和重叠范围，选择最接近的受支持身份。
  检查每个视角的生成结果。如果在检查对齐与输入之后质量仍不足，
  使用自己的配对录制数据[对 Transfer-Auto 进行后训练](../../post-training/README.zh-CN.md#quickstart-fine-tune-the-released-model)。
  对于流式生成，随后[将适配后的 Transfer-Auto 检查点蒸馏为 Sim-Auto](../../../cosmos3-nano-sim-auto/post-training/SKILL.md)。
  对已发布的蒸馏学生模型进行普通 SFT 并不是推荐的适配路径。

重定向需要场景几何、标注和经过验证的车辆位姿；仅有 RGB 或 WSM MP4 不够。
该过程准备的是重新渲染所需的几何数据，并不会同步变换已有 RGB 视频。
保留原生数据与重定向数据的独立副本。
**不要把重定向后的 WSM 与未改变的自定义相机组 RGB 配对**，用作初始条件或训练监督：
它们的视点已不再匹配。初始 RGB 必须与所选输出相机及时间一致。
对于自定义相机组的后训练，应跳过参考相机组重定向，保留对齐的原生相机 RGB／WSM 配对。
相机重定向工具不适配 LiDAR；联合生成仍需要受支持的 LiDAR 几何和同步控制。

<a id="preserve-camera-identity"></a>
### 保持相机身份

检查点为每个受支持的相机键学习了独立视角嵌入。Framework 通过 `camera_key` 查找该 ID；
不会根据像素、描述文本、文件名或相机在列表中的位置推断相机朝向。
名称正确的文件仍然可能包含错误视角。

使用模型的[相机身份表](../../post-training/references/data-contract.zh-CN.md#camera-identities)，
以及用户的标定或经验证的渲染器映射。先比较光轴方向，再比较裁剪／缩放后的有效 FOV 和镜头投影。
标称的广角／长焦标签不能确定是针孔还是 F-theta 标定。文件名不是物理朝向的证据。

考虑所有受支持身份及整个相机组，而不只是通常使用的七个。
标记较大的方向／FOV 差异、鱼眼与针孔不匹配、不确定的重叠范围和重复分配。
使用唯一的受支持相机键。记录几何差异，以便指导重定向或后训练。

| 源相机／控制 | 已验证的方向／FOV／投影 | 模型相机键 | 学习到的 ID | 差异／不确定性 |
| --- | --- | --- | --- | --- |

ID 来自身份表，而不是列表位置。例如，前广角／左后／前长焦保留 0/4/6，而不是 0/1/2。
重新排序或删除视角时，保留控制、RGB、描述文本和输出之间的对应关系。
对于 Framework 请求，保留显式的 `multiview.views` 列表。
保留自定义子集时，不要再添加用于选择预设视角数量的覆盖参数。

宽视野后视相机并不自动等同于后长焦相机，鱼眼别名也不会重新投影其像素。
对于仅检查请求，提出映射建议；仅在请求输入准备时应用映射，并保留源通道来源信息。

<a id="use-camera-rig-explorer-for-your-own-rig"></a>
### 为自己的相机组使用 Camera Rig Explorer

打开离线 [Camera Rig Explorer](../../../cookbooks/cosmos3/simulation/auto/wsm/docs/camera-rig/guide.md)，
在同步的 2D／3D 视图中检查参考相机位置、观察方向、覆盖范围与内参。
在本地打开 `.agents/skills/cookbooks/cosmos3/simulation/auto/wsm/docs/camera-rig/index.html`，
并将其支持文件保留在旁边。无需上传任何内容。

1. 检查两套参考标定，并比较自己的相机光轴、有效 FOV、投影、位置和重叠范围。
   可以按照查看器的[几何 JSON 格式约定](../../../cookbooks/cosmos3/simulation/auto/wsm/docs/camera-rig/guide.md#import-another-calibration)
   导入自己的相机组；它需要准备好的射线／截面，而不是任意原始标定文件。
2. 为自己的每台相机分配最接近的受支持 `camera_key`，作为推理和 Transfer-Auto 后训练的起点。
   在上表中记录映射，包括不匹配之处。查看器帮助比较几何；
   它不会自动选择模型 ID，也不会修改推理请求。
3. 在训练和推理中保持该分配。使用实际相机标定渲染 WSM，
   并保持匹配的 RGB、WSM 和描述文本路径相互对应。
   嵌入 ID 应使用身份表中的值，而不是查看器的显示编号。
4. 测试一个简短的同步场景，检查每个视角及重叠区域。
   对于显著的相机组差异，先使用配对数据适配 [Transfer-Auto](../../post-training/README.zh-CN.md)；
   如果需要流式生成，再[将适配后的模型蒸馏为 Sim-Auto](../../../cosmos3-nano-sim-auto/post-training/SKILL.md)。

<a id="3-check-controls-and-synchronization"></a>
## 3. 检查控制与同步

将实际渲染器版本／配置和类别转换与模型预期的 [WSM 约定](wsm-conventions.zh-CN.md)比较。
相同颜色或 MP4 编码器标签不能确定正确的渲染器版本。

探测分辨率、FPS／PTS、帧数、区间、偏移和解码错误。
实际查看同步概览帧，包括起止时刻；对于影响结论的歧义，再检查相关帧或局部裁剪图。
将对应事件与源时间戳核对，以验证同步。如果无法查看帧，报告视觉检查未完成。

分别记录实际源采样率、请求中的模型 `fps` 和保存视频的播放速率。
参考配置使用 30-FPS 相机；较低速率输入需要明确进行质量检查。
对于 10-FPS 数据，请遵循 [FPS 故障排查指南](input-and-execution.zh-CN.md#source-timing-model-fps-and-playback-fps)。
FPS 标志或容器头修改不会对控制重采样；
联合生成还需要对齐的 LiDAR 时钟和源扫描 ID。

检查类别含义、车道／人行横道／边界约定、信号状态／正面／背面及投影。
未知信号不等于红灯、绿灯或熄灭。卡车类别包围盒不能证明具体卡车子类型；
类别颜色不是车漆。不要为了弥补不确定的上游标签而编造参与者或信号。

比较源 RGB 与 WSM，检查相机对齐并调查缺失物体或检测错误。
编写描述文本时，遵循下述来源规则。

<a id="4-delegate-caption-authoring"></a>
## 4. 按专用指南编写描述文本

对于新建／扩写描述文本，阅读并遵循随附的 [AV 描述文本指南](caption-guide.zh-CN.md)，
包括其描述文本策略。传入同步媒体／时间信息、渲染器语义、物理方向和所选输出键、
映射不确定性、四项属性及其来源，以及未被排除的兼容已有文本。
不要用近似别名替代物理几何。

默认生成**覆盖全部所提供视角的长篇带时间戳描述文本，每个视角的所有文本块合计 300–400 个词（仅计正文）**。
段落形式、较短长度和视角子集都是可选项。额外视觉审阅默认关闭；
编写过程中的 WSM 检查仍为必需。不要额外强制加入方案确认或反复审阅流程。

对于仅检查请求中的已有描述文本，提供带视角／时间证据的语义矛盾报告及修改建议；
不调用编写流程，也不重写原文。根据含义检查一天中的时段、天气、路面状况和地理环境：
“夜间”与阳光照射的建筑相矛盾，但沿海场景的后视画面不必显示大海。

在共享时间线上联合检查描述文本：同一参与者在不同视角与时间中必须保持兼容的颜色、类型和物理运动。
例如，不要在一个视角说同一辆车是蓝色、另一个视角说它是白色，
也不要同时将自车描述为停车和行驶。由于相机朝向不同，屏幕空间运动、反射和可见性不同可能是正确的；
不要强求措辞、可见时间或段落边界相同。

<a id="5-check-packaging-and-effective-sampling-settings"></a>
## 5. 检查打包与实际采样设置

遵循[输入与执行约定](input-and-execution.zh-CN.md)：

- 将正文与相机／相机组的上下文前缀分开；前缀只添加一次。
  检查实际生效的文本，不要擅自把前视提示词复制到所有视角。
- 检查键覆盖范围、顺序、sidecar 边界、截断、tokenizer 限制和实际时长。
  描述文本加载可能决定生成帧跨度。
- 对于仅前视描述文本的比较，为每个所选视角保留具有相同帧边界的 sidecar，
  并对其他视角使用 `"caption": ""`。检查实际生效文本；
  JSON `null` 和字符串 `"None"` 都不是空描述文本。
- “相机键到描述正文”的 JSON 映射不是可执行的推理请求。
  在描述文本比较中，保留控制、初始图像和所有非描述文本设置。
- 报告权重／变体、条件模式、视角 ID、分辨率、FPS／帧数、
  随机种子、步数、shift、guidance，以及实际正向／负向文本。

对于未蒸馏的 Transfer-Auto 模型，guidance 3 是起点；
1.5 是低 guidance 比较选项，而不是通用默认值。
复现用户运行时保留明确设置。不要将这些设置应用于因果模型或蒸馏模型。

在请求时使用随附的[负向提示词](../assets/negative-prompt.txt)。
在独立各视角描述模式下，使用运行时的 `per_view_negative_prompt` 字段；
普通负向字段并不等价。建议更改前，检查其措辞是否与有意要求的雾、雨或镜头效果冲突。
其他运行时接口需要各自检查解析后的字段；不要照搬不受支持的标志。

<a id="6-make-results-inspectable"></a>
## 6. 使结果便于检查

对于已授权的生成，保存各相机视频的压缩预览副本，以及 **50% WSM／50% 生成 RGB 叠加图**，
并保留原始文件。使用实际输入模型的控制，保持相同区间／裁剪／缩放。
不要为了制作混合图而拉伸输入或使其错位。复用可用工具；无需新建框架。

按相机和时间描述失败，区分观测与假设。
在归咎于映射、描述文本或模型泛化之前，将源控制与保存的模型输入进行比较。
检查每个所选视角，并依据标定确认其相机身份。

提出最小的对照实验方案：固定检查点、条件、控制、随机种子，
以及除疑似原因之外的所有设置。仅在请求时启动。
结束时说明已检查／建议／已应用的映射、实际设置、输出路径和剩余不确定性。
区分输入检查、已完成的生成，以及经过视觉检查的质量。
